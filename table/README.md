# TABLE — SkyWay SFU 卓アプリ

`tower/` は SkyWay の SFU ルームを使った、ブラウザー上の共有テーブルです。カード画像はリポジトリ内の `../cards/` を再利用します。

## ローカルで起動する

`file://` ではなく HTTP でリポジトリルートを配信してください。Web Crypto と ES modules を使用します。

```sh
python3 -m http.server 8000
```

<http://localhost:8000/tower/> を開きます。SkyWay SDK は esm.sh、フォントは Google Fonts から読み込むため、外部ホストへ接続できる環境が必要です。

[`app.js`](./app.js) 冒頭の2つの定数にSkyWayの値を設定してください。

```js
const API_KEY = '';
const PASSWORD = '';
```

`API_KEY` は SkyWay のアプリケーションID、`PASSWORD` は Secret Key です。ブラウザー内で `SkyWayAuthToken` を署名し、ルームに限定した1時間有効のトークンを作って `SkyWayContext.Create` に渡します。これはローカル試験用です。ブラウザーで配信するJavaScriptから秘密鍵を隠すことはできません。Secret Keyを設定した状態で一般公開しないでください。本番公開では、Secret Keyをサーバーに保管し、権限を絞った短期トークンを発行するバックエンドに置き換えてください。

部屋を作成したら **招待リンクをコピー** でURLを共有します。参加者は同じ部屋IDと表示名を入力します。部屋IDは半角英数字、`-`、`_` の1〜48文字です。

## 卓の操作

- ネームプレート、ローカル画像、個人のコインを卓に置けます。画像は選択後のサイズスライダーで40〜250%に拡大縮小できます。
- 画像はブラウザー内でWebPに変換・圧縮して共有します。圧縮後の上限は1枚5 MB、元画像は24 MB以下です。画像データはSkyWay DataStream用に分割して送信します。
- 52枚入りのトランプ箱を最大2箱まで追加できます。箱を押すと1枚を自分の手札に引きます。箱は削除でき、確認後その箱のカードはゲームから取り除かれます。アイテムはドラッグで移動でき、ダブルクリックで回収します。手札のカードは裏向きで卓に出し、クリックで表裏を切り替えます。
- 参加者全員が箱を選んで配れます。残りを均等に配るか、1人あたりの枚数を指定できます。除外するランク（例: `A, K, 7`）と箱に残す枚数も指定できます。**全回収** は手札と卓上のカードをそれぞれ元の箱に戻します。
- 共通・無限のコインケースと個人の所持コインを相互に移せます。個人コインを卓に出すと所持数から差し引きます（負数入力可）。卓のコインはダブルクリックで回収して所持数に加算します。
- 所持コインは指定枚数または「所持コインをすべて戻す」でコインケースに返せます。
- ホストは「場をすべて片付ける」で卓上オブジェクトと描画を消去できます。卓上のカードは箱へ戻り、コインは元の持ち主に戻ります。手札は保持されます。
- 卓の下のペン・消しゴムで描画できます。描画内容はリアルタイムで共有され、線にマウスを合わせると記入者を表示します。描画中は卓上アイテムを操作できず、全消去はホストのみ実行できます。
- ロビーには共通のSkyWay公開一覧に登録された部屋が表示されます。部屋は初期状態で公開され、ホストが部屋設定から公開・非公開を切り替えられます。招待リンクからの参加も引き続き利用できます。
- 通常チャットはルーム参加者に共有します。ホストのブラウザーが開いている間は、直近50件を新しい参加者にも表示します。個別チャットは送信先の画面だけに表示しますが、通信自体は共有DataStream上の平文です。受信対象外の参加者も開発者ツール等で通信データを確認できるため、秘密情報は送らないでください。
- ホストが通常の退出操作をするとルームを閉じ、他の参加者も退出します。ブラウザーのクラッシュやネットワーク切断は、SkyWayが切断を検知した時点で解散します。

## 通信方式と状態

SkyWay SDKでは `SFURoom` から `DataStream` をPublishできません。そのため、参加者一覧とルームのライフサイクルにはSFUルームを使い、状態・チャットのDataStreamには対応するP2Pルームを併用します。2つのルームで各参加者に同じ一意なSkyWayメンバー名を設定し、P2Pの送信者をSFUルームの参加者に対応づけます。ゲームデータの通信はP2Pであり、SFUのように大人数へ拡張できる構成ではありません。

[`engine.js`](./engine.js) は通信方式から独立した状態 reducer です。ホストが操作を検証して状態を配信します。手札を含む状態は、参加者ごとにP-256 ECDH鍵で共有した鍵を使ってAES-GCM暗号化してから送信します。他の参加者へは暗号文のみ送ります。これは協調的なクライアント側保護で、信頼できるゲームサーバーや不正対策を意味しません。

静的なクライアントだけでは、ホストが突然オフラインになったことをサーバー側で検証できません。そのため、ホスト切断を検知したゲストがルームを閉じる権限を持ちます。この挙動は利便性とのトレードオフです。

```sh
node --test tower/engine.test.cjs
```
